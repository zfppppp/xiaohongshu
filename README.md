# BriefLab · 种草证据台

**从真实用户问题，走到一份有来源、可执行、能复盘的轻薄本内容简报。**

周枫浦 · 小红书商业培训生求职项目 · 2026.09

这是一款可运行的内容决策工具，覆盖选题证据、简报编写、表述漏项提醒和交易实验复盘。聚焦轻薄本类目，与我的京东轻薄本采销、直播和校园用户调研经历相连。它是新做的独立求职项目，没有在京东或小红书落地。

**先看思考：** [行业调研与产品取舍](docs/RESEARCH.md)　·　[3 分钟演示路线](docs/DEMO.md)　·　[验证记录](docs/VALIDATION.md)

## 为什么值得做

一位用户追问“26 小时续航对应什么场景，办公到底能用多久”；另一位用户关心办公时的风扇噪音。这些问题暴露了一个可研究的缺口：**参数描述与个人任务之间，缺少可迁移的解释。** [续航原帖](https://club.lenovo.com.cn/thread-9445640-1-1.html) · [噪音原帖](https://club.lenovo.com.cn/thread-7957358-1-1.html)

独立测试、厂商测试条件和 Windows on Arm 兼容性说明，为“按场景补证”提供依据。两篇目的抽样帖子仅证明疑问存在，不能证明小红书人群的痛点发生率。商家愿不愿意用本工具，仍待验证。

灵犀已有洞察，蒲公英已有合作与复盘。本项目不假定平台工具缺位，而是把一次具体内容任务中的**问题、来源、承诺、待验证项、结果口径**接在一起。

```mermaid
flowchart LR
 A[公开用户问题] --> B[来源与反证]
 B --> C[场景假设]
 C --> D[内容简报与补证清单]
 D --> E[同口径观察]
 E --> F[继续验证 / 修改 / 停止]
```

## 可以实际操作什么

| 模块     | 可完成的任务                                            | 关键判断                                                   |
| -------- | ------------------------------------------------------- | ---------------------------------------------------------- |
| 选题证据 | 切换续航、噪音、兼容性；打开原文                        | 区分用户个案、测试、厂商说明与推断，保留反证               |
| 内容简报 | 填写 SKU、任务、来源和测试条件；编辑草稿；下载 Markdown | 通用研究不能替具体商品背书；未填项保留“待补证”             |
| 表述检查 | 找出缺链接、缺软件任务及绝对化表述                      | 显式规则可解释；不假装完成事实核查                         |
| 实验复盘 | 编辑两组数据、导入 JSON、导出含输入记录的复盘           | 买家与订单分母分开；不同口径不计算差异；不自动宣布因果效果 |

例如默认演示文案说“续航 26 小时、一整天不用充电、所有办公软件都流畅”。工具会列出补证项；填写条件后仍保留人工复核，避免“字段填满 = 商品结论真实”。

## 商业指标的取舍

- 支付转化率 = 去重支付买家 ÷ 商品访问 UV，不能用订单数代替买家数。
- 全额退款订单率 = 全额退款订单 ÷ 支付订单；部分退款体现在退款后收入中。
- 项目贡献 = 退款后收入 − 可变成本 − 媒体费 − 制作合作费。未录入固定成本和税项，不等于净利润。
- 未确认同 SKU、权益、归因、统计和退款窗口时，不计算转化差异；确认后也只展示观察差异，不称为增量。

演示数据均为人工构造，没有平台后台数据或已验证的增长成绩。JSON 导入在浏览器内解析；本项目代码不把导入数据发送给服务器。编辑仅在当前页面内存中，刷新前请导出。

## 快速运行

需要 Node.js 22.13+ 和 pnpm 11.19.0。

```bash
pnpm install --frozen-lockfile
pnpm dev
```

打开 `http://localhost:3000`。无需 API Key、数据库或平台账号。

```bash
pnpm test          # 业务规则与边界测试
pnpm typecheck     # TypeScript 检查
pnpm build:static  # 生成 out，可部署到静态托管
pnpm preview:static
```

`pnpm build` 保留模板的 Vinext 服务端构建入口；求职展示使用已经验证的 `build:static`，两者共用 `app/page.tsx`。

## GitHub Pages

仓库中已提供 `.github/workflows/pages.yml`。在仓库 **Settings → Pages → Source** 选择 **GitHub Actions**，再运行 **Publish BriefLab** 工作流。工作流会先测试、检查类型和构建，再部署。实际网址以 Actions 运行结果为准；本地构建通过不代表线上已发布。[GitHub 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)

## 文件与实现

```text
app/page.tsx             交互页面
app/globals.css          响应式界面
lib/evidence.ts          证据摘要、来源和选题假设
lib/domain.ts            文案检查、简报导出、实验计算与导入校验
tests/domain.test.ts     可重复运行的业务测试
docs/RESEARCH.md         调研、替代方案、反证与验证计划
docs/DEMO.md             演示路线和面试追问
docs/VALIDATION.md       已完成验证与未验证事项
```

React + TypeScript + Vite / Vinext；使用已有 UI 组件和确定性模板。没有大模型在线调用、自动爬虫或黑箱“机会评分”。AI 辅助完成资料整理与代码实现；项目作者需要理解并复核来源、业务假设和计算口径。

## 下一步：怎样证伪

计划让 3 位参与者交叉使用文档和工具完成相似简报，比较耗时、漏项和无依据表述。试点目标是中位耗时降低 20% 且错误不增加，**尚未执行**。如果没有优势，优先修改模板或停止扩功能。业务实验另行进行，不用任务效率冒充销售提升。
