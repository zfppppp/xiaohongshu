# BriefLab · 内容经营工作台

**把问题、证据、简报与经营复盘，放进一个能持续使用的项目。**

[打开在线工作台 →](https://zfppppp.github.io/xiaohongshu/) · [使用指南](docs/GUIDE.md) · [完整案例讲解](docs/DEMO.md)

免安装、免登录。任何人都可以从空白项目开始，不限于轻薄本。项目自动保存在使用者自己的浏览器；导出 JSON 备份后，可以在另一台设备导入。你的工作数据不会被本项目代码上传到 GitHub 或其他服务器。

在轻薄本研究中，一位用户追问宣传续航对应什么任务，另一位用户关注办公风扇噪音。这使我从“写卖点”转向“解释具体任务、保留证据与适用边界”。[续航原帖](https://club.lenovo.com.cn/thread-9445640-1-1.html) · [噪音原帖](https://club.lenovo.com.cn/thread-7957358-1-1.html)

## 完整案例看什么

打开工作台 → 完整案例 → 依次查看项目概览、证据资料、内容简报、数据复盘。

案例保留公开来源、未实测事项与模拟经营反例：支付转化由 3% 到 4%，但全额退款订单率由 15.79% 到 28%，项目贡献由 6,868 元降至 1,764 元。此时应先核查退款和成本，而非只看转化。所有交易数字均为模拟，不代表真实商家表现或因果结论。

## 指标与边界

- 支付转化率 = 去重支付买家 ÷ 商品访问 UV。
- 全额退款订单率 = 全额退款订单 ÷ 支付订单；部分退款体现在退款后收入。
- 项目贡献 = 退款后收入 − 可变成本 − 媒体费 − 制作合作费。不含未录入的固定成本和税项，不等于净利润。
- 每千访客贡献 = 项目贡献 ÷ 商品访问 UV × 1000，仅按当前观察窗口摊销，不预测放量收益。
- 缺失数据不按零处理；只有填写来源、统计窗口、归因、退款窗口并确认同口径后，才计算组间转化差异。
- 自然内容对比仅是观察差异，不能宣布显著性或因果效果。编辑检查不代替事实核查。

## 本地数据怎么保存

使用浏览器本地存储，**同一浏览器、同一网址**才能继续原有项目。公开 GitHub Pages 与私人预览是不同网址，数据不互通；用备份迁移。清除网站数据或退出无痕模式可能删除项目，请定期导出。

工作空间容量为 4 MB（UTF-8 备份大小），最多 100 个项目。保存失败会明确提示并保留当前页面内容供导出。同一网址使用 Web Locks 保证一个标签页负责编辑；其他标签页只读。使用支持 Web Locks 的现代浏览器；不支持时只允许查看和导出。没有跨设备云同步、多人协作、后台数据连接或自动爬虫。

## 运行与验证

需要 Node.js 22.13+、pnpm 11.19.0。无需 API Key 或数据库。

```bash
pnpm install --frozen-lockfile
pnpm dev
pnpm test
pnpm typecheck
pnpm build:static
pnpm preview:static
```

GitHub Actions 自动测试、检查类型、构建并发布 Pages。静态部署使用 `out/`；`pnpm build` 保留原 Vinext 服务端入口，未作为本次交付路径验证。

主要实现：`app/page.tsx` 交互界面；`lib/workspace.ts` 项目、备份与 CSV 规则；`lib/use-workspace.ts` 本地保存与编辑锁；`lib/domain.ts` 经营计算；`lib/evidence.ts` 公开案例资料。React + TypeScript + Vite / Vinext；没有在线大模型调用。

代码由 AI 辅助开发，作者负责理解并复核研究、业务规则与实现。下一步仍应让真实运营人员完成任务，验证是否减少准备耗时和漏项，不把功能完成包装成业务增长成果。公开资料归原作者；非小红书官方产品。
