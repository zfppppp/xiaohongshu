# 3 分钟完整案例路线

打开[公开工作台](https://zfppppp.github.io/xiaohongshu/)。先展示首页：工具从真实使用者的空白项目开始，示例单独提供。

## 0:00–0:40：从问题到任务

点击“完整案例”，查看“项目概览”。说明目标人群、续航问题、内容目标和执行清单；这是一份计划，没有已执行的商品实测或投放结果。

讲法：“我的轻薄本采销和直播经历，让我注意到参数与实际任务之间的解释差距。工具把任务、证据和交接内容放到同一个项目里。”

## 0:40–1:20：保留依据与反证

进入“证据资料”。展示用户原帖、独立测试、厂商说明与监督抽查反证，打开原始链接。说明两篇目的抽样帖子只能证明疑问存在，不能代表小红书人群规模；使用者必须自己核对。

如需展示编辑，点击“复制到我的项目”，在副本里添加一条自己的证据。勾选引用后，简报会带上来源、发现和边界。

## 1:20–2:00：交付能执行的简报

进入“内容简报”，查看标题、假设、反证、拍摄清单和正文。“完整预览”呈现实际导出内容。商品尚未实测，所以相关结果保持待补，不填一个好看的续航数字。

导出 Markdown 简报，说明它可以交给创作者继续执行；项目中还能安排负责人、日期与完成状态。

## 2:00–2:40：转化上涨不等于经营改善

进入“数据复盘”。说明数字全部为模拟：A、B 商品访客均 1,200，支付转化分别 3% 与 4%，但全额退款率由 15.79% 到 28%，贡献由 6,868 元降至 1,764 元。

工具同时显示每千访客贡献并提示先核查退款和成本。讨论有哪些其他解释，例如流量结构或成本归集；不能据此认为内容造成退款。

在副本中改一项数据，确认开关会取消，组间差异暂停计算；填写来源、窗口与归因再确认。导出复盘会留下原始输入和自己的决策。

## 2:40–3:00：实际使用与下一步验证

回到首页，演示新建空白项目、备份和导入。任何人都能免登录使用；本地保存需要自行备份，尚无云同步。

讲法：“我把调研判断做成可操作流程，但还没有真实商家的使用反馈或增长结果。下一步应观察运营人员能否更少漏项、更快交付，如果没有优势，就调整流程而非继续堆功能。”

## 追问准备

- 为什么不替代灵犀、蒲公英？它们已有平台洞察与合作能力，本工具聚焦具体内容任务的证据交接与个人复盘，没有平台接口。
- 为什么不自动生成？先保证使用者提供依据；自动生成不能替代原始记录。
- 代码是谁写的？如实说明借助 AI 开发，自己负责理解、复核业务假设、来源与计算口径。
- 怎么证明有商业效果？当前无法证明。真实任务试验与经营试验还需分别执行。
