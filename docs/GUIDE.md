# BriefLab 使用指南

## 第一次使用

1. 打开[公开工作台](https://zfppppp.github.io/xiaohongshu/)，点击“新建项目”，填写名称和品类。
2. 在“项目概览”定义商品、人群、核心问题、业务目标、负责人和日期。
3. 在“证据资料”点击“添加证据”：记录标题、发现、出处、时间和适用边界。有原文则附链接；线下记录可填写访谈代号或记录编号。阅读原文后再勾选“已核对”。
4. 勾选需要“引用到简报”的证据；进入“内容简报”，填写标题、假设、反证、拍摄清单和正文。旁边的检查帮助发现漏项。
5. 用“完整预览”检查全部导出内容，再点击“导出简报”。Markdown 文件包含当前项目资料、引用、执行任务和未完成项。
6. 在项目概览添加任务、负责人和截止日期，完成后勾选。

证据 URL 不会自动抓取；需要自己阅读和整理。工具也不会调用大模型自动替你编写结论。

## 填写复盘

“数据复盘”可以直接填数，也可以下载空白 CSV 表格，用 Excel 填完后另存为 **CSV UTF-8** 并导入。保留中文标题行和两组记录，名称区分 A、B；不要用千分位分隔符填写数字。明确没有费用时填 0，未知则留空等待补充。

字段顺序：组别、商品访问UV、支付买家UV、支付订单、全额退款订单、退款后收入、可变成本、媒体费、制作合作费。

支付买家是去重人数，订单可以一人多单。退款后收入扣除全额及部分退款，可变成本包括商品、平台、履约和售后成本，媒体与制作费用按组分摊。

补充数据来源、统计窗口、归因方式和退款窗口，核对同商品及权益等前提后勾选确认。数据或口径改变会清除确认。工具显示观察差异和下一步检查方向，不自动宣布因果或决定放量。在“我的复盘与下一步决策”写自己的判断，然后导出复盘；导出包含输入记录与口径。

## 保存、备份与迁移

- 顶部显示本地保存状态。正常情况下，修改立即保存在当前浏览器，刷新后可继续。
- 首页右侧下载图标：备份全部项目；项目概览“导出项目”或右上角“…”：备份单项目。
- 换电脑或换网址后，从首页“导入项目”选择 JSON 备份。导入为新副本，不覆盖现有项目，且需要重新确认比较口径。
- 使用本工作台的代码不会上传项目数据。GitHub 托管提供网页资源，不接收你的表格或内容记录。
- 本地保存不等于云备份。清理浏览数据、无痕窗口退出或换浏览器都会影响访问；请定期导出。
- 同一网址的另一个标签页只读，避免相互覆盖。要切换编辑窗口，关闭正在编辑的一页，再刷新另一页。
- 存储异常时保留当前页面，先导出当前备份。若启动时记录无法解析，可下载原始备份后再重置空间。
- 每个工作空间最多 100 个项目、每项目 500 条证据和 200 个任务，备份总大小不超过 4 MB。容量不足时导出并删除旧项目。

## 完整案例

点击首页“完整案例”。这是独立只读案例，不占用自己的项目空间。可以依次查看四个模块，也可以“复制到我的项目”后编辑。

公开资料是真实来源；商品实测尚待执行，交易数据明确为模拟。复制案例不会自动变成真实业绩；需要替换数据并更新来源说明。

## 当前范围

适合个人内容运营的资料与简报工作，以及两组汇总数据复盘。没有云端同步、团队权限、自动发布、平台后台连接或文件素材库。简报与复盘都需要使用者核对事实和业务口径。
